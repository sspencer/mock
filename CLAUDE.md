# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

`mock` is a single Go binary. It turns REST Client-style `.http` files into a local HTTP mock server with hot reload and an admin request-log UI. The pages in `docs/` (indexed by `docs/README.md`) document the user-facing behavior (file dialect, placeholders, matching, ports, admin API) and are the spec. Keep them in sync when behavior changes. `README.md` is a short introduction (install, a first mock, the admin UI screenshot, a feature list) that links to those pages; keep it short, and add a line there only for a headline feature. `docs/ideas.md` is a list of ideas, not spec; delete an idea's row once it is implemented. `docs/` is also published as a site by MkDocs (`mkdocs.yml`, hooks in `docs-site/hooks.py`, the Docs workflow); a new page must be added to the `nav` in `mkdocs.yml` and to `docs/README.md`. `docs/examples.md` describes `examples/gallery/`, whose files `mockhttp/gallery_test.go` drives request by request.

## Commands

```sh
make verify        # fmt-check + go vet + go test ./... + node UI tests (what CI runs)
make fmt           # format Go files (verify never rewrites)
make test          # Go tests only
make test-ui       # node --test internal/ui/tests/*.test.mjs (Node 22+, no deps)
make test-browser  # headless Chrome UI tests in internal/ui/browser/ (skipped without Chrome; CHROME_BIN)
make docs          # build the docs site (MkDocs, strict: broken links/anchors fail); make docs-serve previews it
go test -race ./...                         # also run before pushing
go test ./mockhttp -run TestName            # single Go test
node --test internal/ui/tests/app.test.mjs  # single UI test file
go run . examples/user.http                 # run locally; UI at http://127.0.0.1:8081/
go run . validate -strict examples/*.http   # lint request files without serving
go run . init /tmp/demo                     # write the starter api.http
go run . check -upstream URL api.http       # drift check against a real API
go run . import -host api.example.com x.har # draft .http sections from a HAR file
go run . match api.http GET '/users?x=1'    # which route answers a request, or why none does
go run . run api.http -- curl -s '$MOCK_URL' # serve on free ports around a command, then the strict report
```

Benchmarks: `make bench` (`mockhttp/bench_test.go` matches against 3,000 routes and renders templates; `restclient/bench_test.go` parses). Fuzz targets: `go test ./restclient -run '^$' -fuzz FuzzParse -fuzztime 10s` and `go test ./mockhttp -run '^$' -fuzz FuzzMatchEscapedPath -fuzztime 10s`.

Project hooks in `.claude/settings.json` run `gofmt -w` on edited `.go` files and `go run . validate` on edited `.http` files (both need `jq`).

## Architecture

The pipeline is: parse `.http` → assign each route a port → serve all ports from one handler → stream request events to a separate admin UI.

- **`restclient/`**: parser. `Parse`/`Load` turn `.http` text into `[]restclient.Method`. A Method holds the name, the method (`Method.Method` is one method, a comma list such as `GET,HEAD`, or `*`; test it with `Accepts`, send `SampleMethod`), status, variables, `MatchHeaders`/`MatchQuery`/`MatchPath`/`MatchBody`/`MatchJSON`/`MatchForm`/`MatchCookies`/`MatchXML` (raw matcher values from `@header.*`, `@query.*`, `@path.*`, `@body`, `@json.*`, `@form.*`, `@cookie.*`, `@xml.*`; JSON/XML paths are parsed by `ParseJSONPath` in `jsonpath.go`; parsed by `ParseMatcher`/`ParseBodyMatcher` in `matcher.go`: exact, `*`, `!`, `~regex`, and the negated `!text`/`!~regex`), response `Headers` (with `@default.header.*` and `Options.Headers`, from `-H`, filled in by `applyDefaultHeaders` for names the section does not set; a default `Content-Type` goes to `DefaultContentType` instead, which `renderer.headers` sends only after the file extension and a specific `http.DetectContentType` sniff fail), body or `< file` ref, delay, and `Source`/`Line` for diagnostics. File-scoped `@vars` can be defined after the sections that use them, so sections are buffered as `pendingSection` and resolved at the end. REST Client allowances: an unnamed `###` (or a request before the first `###`, with its leading comments) is named after `# @name` or its request line (`pendingSection.unnamed`), `//` lines are comments, and an `HTTP/x` version or a bare target (`GET`) is accepted on the request line. `warnRESTClientSyntax` in `mockhttp/server.go` warns about request variables and request settings. `Parse` is `scanFile` (sections and file-scoped definitions) plus `expandImports` (`import.go`: `@import` splices in another file's file-scoped definitions, recursively, with cycle detection; each definition keeps its `file` for errors, and `Method.Imports` lists the imported files for the watcher). Errors are `file:line:` formatted.
- **`main.go`**: only wires signals, sets `cli.Version` from the link-time `main.version`, calls `cli.Run`, and maps errors to exit codes with `cli.ExitCode`.
- **`internal/cli/`**: the command. `Run(ctx, args, stdin, stdout, stderr, logger)` is the testable entry point (`run.go`). It parses flags (`config.go`; `-l json` swaps the logger for a JSON handler on stdout and turns the banner and route list into records via `announceJSON`/`showMethods`; `-e`/`-E` select a REST Client environment in `env.go`, whose values become `restclient.Options.Defaults`, the lowest-precedence variables, below `@name` and `-v`), loads the input (`input.go`: files, `-d` directories whose `.http` files load after the files, stdin, or a positional directory, which runs as a plain static file server with no admin UI), builds a `portPlan` (`ports.go`), binds every mock port before serving, then serves one `mockhttp.Server` on all mock listeners plus a separate admin listener (`serve.go`). With `--strict`, shutdown writes the coverage report from `strict.go` and fails on unmatched requests.
- **`internal/cli/ports.go`**: a route's port comes from the port in its URL target, else `@port`, else `-p`. Hot reload may change routes but can't open new ports, so `plan.resolve` rejects that case.
- **`internal/cli/watch.go`**: fsnotify watcher on the request files and their `< path` bodies, plus every directory under each `-d` tree (`treeEventLocked` decides which tree events reload; `reloadMockFiles` rescans the trees). On change, `reloadMockFiles` (`reload.go`) re-parses and calls `Server.SetMethods` (an atomic swap that bumps the revision). A failed reload keeps the old routes and records the error for `/state` and the UI banner. `Reconcile` updates the watched dependency set after each reload. The `reloader` in `reload.go` serializes every trigger (file events, `POST /reload` via `Server.SetReloader`/`ServeReload`, SIGHUP in `hangup.go`, and `-i` polling, which compares `snapshotFiles` of the dependencies).
- **`mockhttp/`**: runtime. `server.go` handles ServeHTTP: match, apply the `--delay`/`--fault`/`--throttle` route defaults (`defaults.go`, `Server.SetRouteDefaults`; a copy of the route, only where it sets no `@delay`/`@fault`/`@throttle`), then any run-time override from `/faults` (`faults.go`: `Server.SetFault`/`ClearFaults`, stored by `routeKey` or `*`, applied by `withOverride`), `@rate-limit` (`ratelimit.go`: a sliding-window `rateLimiter` per route and `@rate-limit.key` value, keyed by `routeKey` so reloads keep it; every response gets `X-RateLimit-*` headers and over budget answers `429` with `Retry-After`), delay (`sampleDelay`: fixed, uniform, or lognormal from `DelaySigma`, capped at p99.99), render, write (through a `throttledWriter` for `@throttle`, `network.go`), then `logRequest`. `-P` profiles are the `networkProfiles` table in `internal/cli/config.go`; keep `usageText` in step. Matching is in `match.go`: the first route in load order (`@fallback` routes after all others) whose port, method, path and matchers all accept the request, that has `@times` answers left (`times.go`: `uses` counters carried across reloads like hits, taken with a CAS so concurrent requests never exceed the limit), and that wins its `@match.chance` draw (`chance.go`, `rollChance`; seeded per route by `@seed` and a draw counter carried across reloads like hits), wins (no rotation). The body is read once (up to 1 MiB) and JSON/form data (URL-encoded, or multipart when the `Content-Type` says so) cookies and XML (`xmlbody.go`) are decoded lazily per request (`requestFacts`). A trailing `*`/`*name` path segment is a wildcard. Templates resolve `{{$name}}` through `templateValues.lookup`: path params, then named regex captures from the matched route's matchers, then query values, then the explicit `$path.*`/`$query.*`/`$header.*`/`$cookie.*` namespaces, then `$json.*`/`$form.*`/`$xml.*` from the body. `{{$fixture.*}}` is resolved by the renderer from the route's `@fixture` JSON file (`fixture.go`, re-read per response; `selectJSON` is shared with `$json`). `{{$request}}` and `{{$request.path}}` read `requestFacts.requestDocument` (`echo.go`). When nothing matches it records near-miss candidates. With `--upstream`, unmatched requests are then forwarded by the `httputil.ReverseProxy` in `proxy.go` (`Server.SetUpstream`; `502` on upstream failure, `508` when its own `Via` pseudonym comes back) and the event's `match.upstream` is set. `Server.SetRedact` (`redact.go`, `-R`) masks credentials in each event (`redactEvent`: headers, query, JSON/form body fields, `Details` text, near-miss reasons, and URLs in a callback's error via `redactURLsInText`; `redactJSON` scans JSON text and masks any value under a sensitive key) before `logRequest` or a callback publishes it. `Server.SetRequestHook` (`events.go`) gets every handled request's real (unredacted) event after `logRequest` publishes the redacted copy; `-r` recording uses it. A matched route with `@proxy` (`Method.Proxy`) is forwarded the same way by `serveRouteProxy`; a URL with placeholders is rendered as the exact target (`proxyTarget`). `warnShadowedRoutes` flags routes an earlier route always beats. `warnInvalidJSONBody` (`jsonlint.go`) renders JSON bodies in the renderer's `sample` mode (unresolved placeholders become `1`) and warns when they don't parse. `template.go` parses templates into nodes (text, placeholder with `| filter`s, `{{#repeat}}` blocks, `{{#each}}` blocks over `$json`/`$fixture`/`$item` arrays whose elements `{{$item.*}}` reads, with `| offset`/`| limit`, and `{{#if}}`/`{{else}}` blocks with a `templateCond`); malformed tags stay literal and become load warnings. Filter implementations are in `filters.go`; filter, block and condition arguments that are `$references` are resolved by `renderer.argValue`. `[field=value]` selectors in names (`fixture.users[id=$path.id]`) have their `$references` substituted by `renderer.expandSelectors` before `selectJSONNodes` filters arrays (`restclient.JSONSegment.Select`). `{{$jwt}}` is in `jwt.go` (secret from `@jwt.secret`). `@fixture` files are JSON, CSV or NDJSON by extension (`fixtureFormat`, `decodeCSV`, `decodeNDJSON`); only JSON ones are editable. `@require` and `@missing = next` are checked at match time by `unavailable` (`require.go`) and make a route step aside like a lost `@match.chance` draw. `@status` templates (`Method.StatusTemplate`) are rendered by `renderStatus` and `@etag = auto` by `bodyETag`/`etagMatches` (`status.go`). `render.go` has the per-response `renderer`: one rng (seeded from `@seed` plus the request, else random) and faker shared by the `< path`, body and headers, `| keep` scopes, and JSON-aware output (escaping inside strings, commas between repeat copies). Generator functions are in `functions.go`. A `< path` file sent unchanged (`renderer.verbatim`) to GET/HEAD with status 200 and no `@stream`/`@fault` goes through `serveFileContent` (`http.ServeContent`: ranges, conditional requests). `@compress` (`compress.go`: `responseEncoding` picks gzip/deflate, `compressBody` encodes) runs before that and turns it off. `@callback` (`callback.go`): after the response is logged, `scheduleCallback` renders every `restclient.Callback` in `Method.Callbacks` (`@callback`, then `@callback.N` in order) with the same renderer and sends them in one goroutine, each after its delay, via `sendWithRetries` (10s timeout per attempt; retries on no response, 429 or 5xx with doubling `callbackBackoff`; cancelled by `Server.Close`); the result is published as a `RequestEvent` with `Callback` set, which `RequestFilter` excludes unless `Callbacks` is true. `@stream` chunking is in `server.go`. `@fault` injection: `truncate` (half the body, then abort) is in `server.go`; `reset` (hijack, linger 0), `hang` (wait for the client or `Server.Close`; skipped for resends), `empty` and `garbage` are `injectConnectionFault` in `network.go`. The event is logged before the fault. Per-route hit counts and the unmatched-request tally for `--strict` are in `coverage.go`; `SetMethods` carries counts over to unchanged routes. The request-event ring buffer (1,000 events) and SSE with session+sequence cursors are in `events.go`. Temporary routes (`temporary.go`: `Server.AddRoutes`/`RemoveRoutes`, `POST`/`DELETE /routes`, `mocktest` `Stub`) live in `Server.temps`; `installLocked` rebuilds `methods` as temporary groups (newest first) then `files` (the request-file routes, which `Methods()` returns), carrying counters over. `Server.Reset` (`POST /reset`, `times.go`) zeroes `@times` and chance counters, clears rate limiters and removes `/faults` overrides, keeping hits and the log. The admin endpoints `/routes`, `/state`, `/clear` are in `inspection.go`/`details.go`/`events.go`; `/requests` (the filtered request log, also `Server.Requests`) is in `journal.go`. `POST /reload` (`ServeReload`, which calls the function given to `Server.SetReloader`) is in `reload.go`. `GET`/`PUT /fixture` (`ServeFixture`, `fixtureedit.go`) reads a route's `@fixture` by route ID and writes it only when the file is a current route's fixture, the content is valid JSON (`checkFixtureJSON`) and the SHA-256 `version` still matches (else `409`), via `writeFileAtomic` under `fixtureMu`. `POST /resend` (`ServeResend`, `resend.go`) builds the request in-process (its `Host` port set as `http.LocalAddrContextKey` so port matching works, but only when `servesPort` finds a route on that port; otherwise any port matches), runs `ServeHTTP` into a discarding writer (recovering `http.ErrAbortHandler` from faults), and returns the new event ID, which `logRequest` stores in the `resendState` from the context along with `RequestEvent.ResendOf`. Admin POSTs need `X-Requested-With` or a JSON content type and reject cross-origin requests.
- **`mocktest/`**: public Go test helper. `Start`/`StartSource`/`StartWith` load routes (ports zeroed so all answer on one `httptest.Server`), and `AssertCalled`/`AssertAllMatched` query `Server.Requests`.
- **`internal/cli/init.go`**: `mock init` writes the embedded `internal/cli/starter/` files (`api.http`, `users.json`), refusing to overwrite without `-force`. `TestInitWritesValidStarter` runs `validate -strict` on the output, so keep the starter warning-free.
- **`internal/cli/runcmd.go`**: `mock run` parses the flags before `--` (with `-p 0 -a 0` prepended so later flags win), sets `config.quiet` and `config.onReady`, and calls `serve` (`run.go`, everything `Run` does after flag parsing). `onReady` starts the command with `MOCK_URL`/`MOCK_ADMIN_URL`; its exit cancels the serve context, which prints the strict report.
- **`internal/cli/match.go`**: `mock match` builds the request (`matchRequest`) and calls `Server.Explain`, a dry run of `selectRoute` in `match.go` that counts nothing and draws no chance; `-response` serves it from a copy of the routes without delays, faults, streams, throttles, rate limits or callbacks.
- **`internal/cli/check.go`**: `mock check -upstream URL` (drift check). `buildSampleRequest` (`sample.go`) is the Go port of the UI's `buildRouteCurl`/`sampleJSONBody`/`sampleFormBody` in `inspector.mjs`; keep the two in step. Each route is answered in-process by a one-route `mockhttp.Server` (delay, fault, stream, rate limit and callback stripped) and sent to the upstream; `compareResponses` diffs status, media type and top-level JSON keys. Exit 1 on drift or errors.
- **`internal/cli/draft.go`**: the Go port of `buildRouteDraft`/`buildRouteDrafts` in `draft.mjs` (keep the two in step; the matched-route variant, where `buildRouteDraft` adds a `# Variant of` comment for an event a route answered, is UI-only and has no Go port). `draftSection` turns an `exchange` (a captured request and response) into a `.http` section; `draftSections` deduplicates by method and path. `mock import` (`import.go`) converts HAR entries into exchanges; `-r`/`--record` (`record.go`) converts each `--upstream`-answered `RequestEvent` from `Server.SetRequestHook` and appends new sections to the file.
- **`internal/cli/validate.go`**: `mock validate` reuses the same load and warning checks as startup. Exit codes: 0 = ok, 1 = errors (or warnings with `-strict`), 2 = usage error.
- **`internal/ui/`**: the admin UI. `ui.NewHandler` mounts the admin API endpoints and serves `static/`, vanilla ES modules embedded via `embed.go` (`ui.Assets`). It injects `ui.Config` (version, mock port, `multiPort`) into the page as the `<script id="mock-config">` JSON. `ui.RequireToken` (`auth.go`) wraps the admin handler for `-t`/`--ui-token`: a Bearer header, `?token=`, or the cookie a `/?token=` page load sets. Keep pure logic in small modules (`traffic.mjs`, `har.mjs`, `inspector.mjs`, `selection.mjs`, `draft.mjs`, `filter.mjs`, `resend.mjs`, `compare.mjs`, `fixture.mjs`, whose `losslessIssue` keeps files the tree view would rewrite in the JSON view; `fixturetree.mjs` builds the fixture editor's tree DOM from those edits; `switches.mjs` turns the route switches form into `/faults` requests) so `internal/ui/tests/*.test.mjs` can unit test it. The stream client (`TrafficStream` in `traffic.mjs`) and inspector selection (`selection.mjs`: none, a request, a route, or a `compare` of two event IDs that lasts while both stay in the log) are explicit state machines: `app.mjs` applies the effects they return and should not grow its own stream or selection globals. `app.mjs` loads once per test run, so config-dependent behavior must be extracted into testable helpers. `internal/ui/browser/` holds the browser-level tests: `cdp.mjs` is a dependency-free DevTools Protocol client (Chrome launched with `--remote-debugging-pipe`, a fresh browser context per page, real mouse and key input), and `admin.test.mjs` builds `mock` (or uses `MOCK_BIN`), serves a small route file on free ports and checks layout, theming, dividers, keyboard and mobile navigation, and resend/compare end to end. They fail on any console error or exception in the page.

Design constraints:
- Plain HTTP only. TLS and CORS support were removed on purpose; don't add them back.
- Headers after the request line are *response* headers. Request matching uses `@header.Name`.
- Releases are tagged `vX.Y.Z` and published by GoReleaser (`.goreleaser.yaml`): archives, the `ghcr.io/sspencer/mock` image (`Dockerfile.release`, from the built binaries; `Dockerfile` builds from source) and a Homebrew cask in `sspencer/homebrew-tap` (needs the `HOMEBREW_TAP_GITHUB_TOKEN` secret). Record release history in `CHANGELOG.md`.
