# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

`mock` is a single Go binary. It turns REST Client-style `.http` files into a local HTTP mock server with hot reload and an admin request-log UI. README.md documents the user-facing behavior (file dialect, placeholders, matching, ports, admin API) and is the spec. Keep it in sync when behavior changes.

## Commands

```sh
make verify        # fmt-check + go vet + go test ./... + node UI tests (what CI runs)
make fmt           # format Go files (verify never rewrites)
make test          # Go tests only
make test-ui       # node --test internal/ui/tests/*.test.mjs (Node 22+, no deps)
go test -race ./...                         # also run before pushing
go test ./mockhttp -run TestName            # single Go test
node --test internal/ui/tests/app.test.mjs  # single UI test file
go run . examples/user.http                 # run locally; UI at http://127.0.0.1:8081/
go run . validate -strict examples/*.http   # lint request files without serving
```

Fuzz targets: `go test ./restclient -run '^$' -fuzz FuzzParse -fuzztime 10s` and `go test ./mockhttp -run '^$' -fuzz FuzzMatchEscapedPath -fuzztime 10s`.

Project hooks in `.claude/settings.json` run `gofmt -w` on edited `.go` files and `go run . validate` on edited `.http` files (both need `jq`).

## Architecture

The pipeline is: parse `.http` → assign each route a port → serve all ports from one handler → stream request events to a separate admin UI.

- **`restclient/`**: parser. `Parse`/`Load` turn `.http` text into `[]restclient.Method`. A Method holds the name, status, variables, `MatchHeaders`/`MatchQuery`/`MatchPath`/`MatchBody`/`MatchJSON`/`MatchForm`/`MatchCookies`/`MatchXML` (raw matcher values from `@header.*`, `@query.*`, `@path.*`, `@body`, `@json.*`, `@form.*`, `@cookie.*`, `@xml.*`; JSON/XML paths are parsed by `ParseJSONPath` in `jsonpath.go`; parsed by `ParseMatcher`/`ParseBodyMatcher` in `matcher.go`: exact, `*`, `!`, `~regex`, and the negated `!text`/`!~regex`), response `Headers`, body or `< file` ref, delay, and `Source`/`Line` for diagnostics. File-scoped `@vars` can be defined after the sections that use them, so sections are buffered as `pendingSection` and resolved at the end. Errors are `file:line:` formatted.
- **`main.go`**: only wires signals, sets `cli.Version` from the link-time `main.version`, calls `cli.Run`, and maps errors to exit codes with `cli.ExitCode`.
- **`internal/cli/`**: the command. `Run(ctx, args, stdin, stdout, stderr, logger)` is the testable entry point (`run.go`). It parses flags (`config.go`), loads the input (`input.go`: files, `-d` directories whose `.http` files load after the files, stdin, or a positional directory, which runs as a plain static file server with no admin UI), builds a `portPlan` (`ports.go`), binds every mock port before serving, then serves one `mockhttp.Server` on all mock listeners plus a separate admin listener (`serve.go`). With `--strict`, shutdown writes the coverage report from `strict.go` and fails on unmatched requests.
- **`internal/cli/ports.go`**: a route's port comes from the port in its URL target, else `@port`, else `-p`. Hot reload may change routes but can't open new ports, so `plan.resolve` rejects that case.
- **`internal/cli/watch.go`**: fsnotify watcher on the request files and their `< path` bodies, plus every directory under each `-d` tree (`treeEventLocked` decides which tree events reload; `reloadMockFiles` rescans the trees). On change, `reloadMockFiles` (`reload.go`) re-parses and calls `Server.SetMethods` (an atomic swap that bumps the revision). A failed reload keeps the old routes and records the error for `/state` and the UI banner. `Reconcile` updates the watched dependency set after each reload. The `reloader` in `reload.go` serializes every trigger (file events, `POST /reload` via `Server.SetReloader`/`ServeReload`, SIGHUP in `hangup.go`, and `-i` polling, which compares `snapshotFiles` of the dependencies).
- **`mockhttp/`**: runtime. `server.go` handles ServeHTTP: match, delay, render, write, then `logRequest`. Matching is in `match.go`: the first route in load order whose port, method, path and matchers all accept the request wins (no rotation). The body is read once (up to 1 MiB) and JSON/form data (URL-encoded, or multipart when the `Content-Type` says so) cookies and XML (`xmlbody.go`) are decoded lazily per request (`requestFacts`). A trailing `*`/`*name` path segment is a wildcard. Templates resolve `{{$name}}` through `templateValues.lookup`: path params, then named regex captures from the matched route's matchers, then query values, then the explicit `$path.*`/`$query.*`/`$header.*`/`$cookie.*` namespaces, then `$json.*`/`$form.*`/`$xml.*` from the body. `{{$fixture.*}}` is resolved by the renderer from the route's `@fixture` JSON file (`fixture.go`, re-read per response; `selectJSON` is shared with `$json`). `{{$request}}` and `{{$request.path}}` read `requestFacts.requestDocument` (`echo.go`). When nothing matches it records near-miss candidates. With `--upstream`, unmatched requests are then forwarded by the `httputil.ReverseProxy` in `proxy.go` (`Server.SetUpstream`; `502` on upstream failure, `508` when its own `Via` pseudonym comes back) and the event's `match.upstream` is set. A matched route with `@proxy` (`Method.Proxy`) is forwarded the same way by `serveRouteProxy`; a URL with placeholders is rendered as the exact target (`proxyTarget`). `warnShadowedRoutes` flags routes an earlier route always beats. `warnInvalidJSONBody` (`jsonlint.go`) renders JSON bodies in the renderer's `sample` mode (unresolved placeholders become `1`) and warns when they don't parse. `template.go` parses templates into nodes (text, placeholder with `| filter`s, `{{#repeat}}` blocks, and `{{#each}}` blocks over `$json`/`$fixture`/`$item` arrays whose elements `{{$item.*}}` reads); malformed tags stay literal and become load warnings. `render.go` has the per-response `renderer`: one rng (seeded from `@seed` plus the request, else random) and faker shared by the `< path`, body and headers, `| keep` scopes, and JSON-aware output (escaping inside strings, commas between repeat copies). Generator functions are in `functions.go`. `@stream` chunking and `@fault` injection (`reset` hijacks and closes with linger 0; `truncate` sends half the body then aborts) are in `server.go`; the event is logged before the abort. Per-route hit counts and the unmatched-request tally for `--strict` are in `coverage.go`; `SetMethods` carries counts over to unchanged routes. The request-event ring buffer (1,000 events) and SSE with session+sequence cursors are in `events.go`. The admin endpoints `/routes`, `/state`, `/clear` are in `inspection.go`/`details.go`/`events.go`; `/requests` (the filtered request log, also `Server.Requests`) is in `journal.go`. `POST /reload` (`ServeReload`, which calls the function given to `Server.SetReloader`) is in `reload.go`. Admin POSTs need `X-Requested-With` or a JSON content type and reject cross-origin requests.
- **`mocktest/`**: public Go test helper. `Start`/`StartSource`/`StartWith` load routes (ports zeroed so all answer on one `httptest.Server`), and `AssertCalled`/`AssertAllMatched` query `Server.Requests`.
- **`internal/cli/validate.go`**: `mock validate` reuses the same load and warning checks as startup. Exit codes: 0 = ok, 1 = errors (or warnings with `-strict`), 2 = usage error.
- **`internal/ui/`**: the admin UI. `ui.NewHandler` mounts the admin API endpoints and serves `static/`, vanilla ES modules embedded via `embed.go` (`ui.Assets`). It injects `ui.Config` (version, mock port, `multiPort`) into the page as the `<script id="mock-config">` JSON. Keep pure logic in small modules (`traffic.mjs`, `har.mjs`, `inspector.mjs`, `selection.mjs`) so `internal/ui/tests/*.test.mjs` can unit test it. The stream client (`TrafficStream` in `traffic.mjs`) and inspector selection (`selection.mjs`) are explicit state machines: `app.mjs` applies the effects they return and should not grow its own stream or selection globals. `app.mjs` loads once per test run, so config-dependent behavior must be extracted into testable helpers.

Design constraints:
- Plain HTTP only. TLS and CORS support were removed on purpose; don't add them back.
- Headers after the request line are *response* headers. Request matching uses `@header.Name`.
- Releases are tagged `vX.Y.Z` and published by GoReleaser. Record release history in `CHANGELOG.md`.
